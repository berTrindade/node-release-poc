# Release Process: Manual Release (Standard-Version)

This document describes the **manual release process** using standard-version for semantic versioning and changelog generation.

## 8 Core Release Process Concepts

### 1. **Versioning**
- **Tool**: `standard-version` package
- **Strategy**: Semantic Versioning (SemVer) based on Conventional Commits
- **Implementation**: Developer runs `npm run release` which:
  - Analyzes commit history since last tag
  - Determines next version (patch/minor/major)
  - Updates `package.json` and `CHANGELOG.md`
  - Creates annotated git tag (e.g., `v1.2.0`)

### 2. **Branching Strategy**
- **Strategy**: GitFlow-inspired with main branch
- **Implementation**: 
  - Feature branches → PR → merge to `main`
  - Releases cut from `main` branch via manual tagging
  - Manual control over release timing

### 3. **Testing & Quality Gates**
- **Local**: Pre-commit hooks (husky + lint-staged + commitlint)
- **CI**: Automated testing on every push/PR
- **Release**: Full test suite runs before GitHub Release creation
- **Implementation**: 
  - `npm test` (Jest + Supertest)
  - `npm run lint` (ESLint)
  - Failed tests block release workflow

### 4. **Tagging & Artifacts**
- **Tagging**: Manual via `standard-version` (creates annotated tags)
- **Artifacts**: npm package tarball (`npm pack`)
- **Implementation**:
  - Developer creates tag locally: `npm run release`
  - Push tags: `git push origin main --follow-tags`
  - CI attaches tarball to GitHub Release

### 5. **Automation (CI/CD)**
- **CI**: Runs on push/PR (lint, test, build)
- **Release**: Triggered only on tag push
- **Implementation**:
  - `.github/workflows/ci.yml` - continuous integration
  - `.github/workflows/release.yml` - release automation
  - Manual trigger via tag push

### 6. **Documentation & Changelogs**
- **Changelog**: Auto-generated by `standard-version`
- **Documentation**: Manual maintenance
- **Implementation**:
  - `CHANGELOG.md` updated on each release
  - Release notes attached to GitHub Release
  - Conventional Commits provide structured history

### 7. **Deployment & Rollback**
- **Deployment**: Manual or triggered by release
- **Rollback**: Git tag-based (`git checkout v1.1.0`)
- **Implementation**:
  - Tagged releases enable precise rollbacks
  - Docker image tagging matches git tags
  - Manual deployment control

### 8. **Monitoring & Feedback**
- **Health Checks**: `/health` endpoint
- **Observability**: Application logs and metrics
- **Implementation**:
  - Health endpoint for readiness checks
  - Release tags enable version tracking in monitoring

## Step-by-Step Manual Release Commands

### Prerequisites
```bash
# Ensure clean working directory
git status

# Ensure you're on main branch
git checkout main
git pull origin main

# Run tests locally
npm ci
npm test
npm run lint
```

### Release Steps

1. **Create release locally** (analyzes commits, bumps version, updates changelog):
```bash
npm run release
```

2. **Review the changes**:
```bash
git log --oneline -5
cat CHANGELOG.md
```

3. **Push release to trigger CI**:
```bash
git push origin main --follow-tags
```

4. **Monitor GitHub Actions**:
   - CI workflow runs tests and builds artifacts
   - Release workflow creates GitHub Release with tarball
   - Check Actions tab in GitHub repository

### Manual Release Benefits
- **Control**: Release timing is in developer's hands
- **Review**: Changes can be reviewed before release
- **Flexibility**: Can skip releases or create hotfix releases easily
- **Visibility**: Clear separation between development and release activities

### Production Extensions
- Add approval workflows for production releases
- Integrate with deployment pipelines (Kubernetes, Docker registry)
- Add release candidate (RC) versions for staging
- Implement automated rollback mechanisms
- Add release notifications (Slack, email)

## Repository Components

### Package.json Scripts
- `npm run release`: Run standard-version (bump, changelog, tag)
- `npm run changelog`: Preview changelog without releasing
- `npm test`: Run test suite
- `npm run lint`: Run ESLint
- `npm run build`: Create distribution tarball

### GitHub Actions Workflows
- **ci.yml**: Runs on push/PR (lint → test → build → upload artifact)
- **release.yml**: Runs on tag push (lint → test → build → GitHub Release)

### Git Hooks (Husky)
- **pre-commit**: Runs lint-staged (auto-fix code)
- **commit-msg**: Validates Conventional Commit format

### Configuration Files
- `commitlint.config.js`: Conventional Commits validation
- `.lintstagedrc.json`: Pre-commit linting rules
- `jest.config.js`: Test configuration
- `.eslintrc.json`: Code linting rules
